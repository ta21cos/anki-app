# チャンクをレベル別に分類して本番へ反映する手順

既存のチャンクを B1・B2・C1 に分類し、教材ごとの区分を保ったまま、フォルダー名の接尾辞でレベルを区別します。カード本文と学習履歴は保持し、所属デッキを変更します。

この文書は、2026年9月14日に本番へ反映した作業の手順と判断基準を記録しています。

## 分類基準

ヨーロッパ言語共通参照枠（CEFR）の記述を参考にした、学習整理用の推定分類です。各カードの公式なレベル認定ではありません。

| レベル | 分類の目安 |
| --- | --- |
| B1 | 日常・基本的な業務の語彙を使い、意味が直接的で比較的単純な表現を入れます。B1 より易しい表現もこの区分に含めます。 |
| B2 | 一般的な業務の抽象語彙、句動詞、比喩的な連語、複数の節や修飾を組み合わせる表現を入れます。 |
| C1 | 低頻度の形式語彙、専門語彙が密集する表現、直訳しにくい慣用表現、複数の高度な構文を組み合わせる表現を入れます。 |

英語の全文と日本語の意味を確認し、語彙の語義・慣用表現・構文を優先して判断します。長さは補助基準とし、語数だけでレベルを決めません。短い専門表現も上位の候補になります。基本語彙だけの長い文は、長さだけを理由に C1 へ上げません。

今回の分類例は次のとおりです。

| 英語 | レベル | 判断理由 |
| --- | --- | --- |
| When would you like to meet? | B1 | 基本語彙による日程調整の定型表現です。 |
| The colleague is on maternity leave. | B2 | `maternity leave` という人事分野の連語を含みます。 |
| We harmonize remuneration packages. | C1 | 報酬制度に関する形式的な専門語彙を含みます。 |

各カードに語数と判断理由を記録します。今回の語数集計では、短縮形とハイフンでつながる語を原則1語として数えました。レベルごとの件数を均等にする調整は行いません。

参照資料は、欧州評議会の[共通参照レベル](https://www.coe.int/en/web/common-european-framework-reference-languages/table-1-cefr-3.3-common-reference-levels-global-scale)と[語彙範囲を含む補遺](https://rm.coe.int/cefr-companion-volume-with-new-descriptors-2018/1680787989.pdf)です。

## フォルダーとデッキの命名

[デッキのグループ化処理](../src/lib/deck-tree.ts)は、最初の `::` の前をフォルダー名として扱います。次の形式でレベルをフォルダー名の末尾に付けます。

```text
変更前: チャンク::L01 現在形・現在進行形
変更後: チャンク B1::L01 現在形・現在進行形
        チャンク B2::L01 現在形・現在進行形
        チャンク C1::L01 現在形・現在進行形
```

画面には「チャンク B1」「チャンク B2」「チャンク C1」の3フォルダーが表示され、その中に教材ごとのデッキが並びます。`チャンク::B1::L01 ...` のように区切りを増やす方式は採用していません。

教材コードと主題は維持します。該当カードがない教材・レベルの組み合わせには、空デッキを作りません。文章デッキは今回の分類対象に含めません。

## 実行前の準備

リポジトリのルートで作業し、既存の Bun と依存関係を使用します。`.env.local` の `TURSO_DATABASE_URL` と `TURSO_AUTH_TOKEN` を読み込み、本番の Turso データベースへ接続します。接続先と対象所有者を確認し、接続情報は文書やログに出力しません。

今回の作業ファイルは、ローカルの `~/.Codex-works/anki-chunk-levels/` に保存しました。

| ファイル | 内容 |
| --- | --- |
| `before.json` | 対象所有者の全デッキ・全カードの変更前データを保存します。 |
| `classification.json` | 各カードの分類、元の所属、移動先、判断理由を保存します。 |
| `classification.tsv` | タブ区切り値（TSV）形式で、全カードの分類と判断理由を閲覧できます。 |
| `migrate.mjs` | 事前照合・反映・検証・復元を実行します。 |
| `migration.test.mjs` | ローカルのデータベースで移動処理を検証します。 |
| `after.json` | 反映後の対象所有者の全デッキ・全カードを保存します。 |
| `verification.json` | 検証結果と件数を保存します。 |

これらの作業ファイルはリポジトリに含まれません。今回の `migrate.mjs` は351枚の分類結果と変更前データに依存し、リポジトリの絶対パスも参照します。新しい環境へ取得したリポジトリだけでは、以下のコマンドは実行できません。別の端末では作業ファイルと参照パスの準備が必要です。

## 既存カードを分類して移動する

### 1. 現在の本番データを保存する

対象は、所有者と `チャンク::` で始まる元デッキ名から特定します。所有者が複数の場合は、名前だけで一括処理せず、今回処理する所有者を確定します。

対象所有者の全デッキ・全カードを `before.json` に保存します。分類対象外のデータも保存することで、反映後に変更されていないことを照合できます。既存のバックアップを上書きしません。

古い教材ファイルではなく、この時点の本番カード本文を分類に使います。過去に編集されたカードがあるためです。

### 2. 全カードの分類表を作る

各カードに次の情報を記録します。

- カード識別子と元デッキの識別子・名前を記録します。
- 日本語と英語の本文を記録します。
- B1・B2・C1 のいずれか一つ、英語の語数、判断理由を記録します。
- 命名規則に従った移動先デッキ名を記録します。

対象カードが漏れなく一度ずつ現れることを確認します。分類表の識別子・所属・本文が変更前データと一致することも確認します。

### 3. 学習履歴を保持する移動処理を用意する

既存カードの移動では、[インポート用スクリプト](../scripts/import-tsv.ts)でカードを作り直しません。既存カードの `deck_id` だけを更新します。

[データ構造](../worker/schema.ts)にあるカードの識別子、本文、復習期日、習熟状態、復習回数、最終復習日時、作成日時を保持します。移動先デッキには、元デッキの所有者、読み上げ言語、`include_in_daily`、作成日時を引き継ぎます。

元デッキは、該当カードがある最初のレベルに改名して再利用します。レベルの優先順は B1、B2、C1 です。残りのレベルには新しいデッキを作ります。これにより、元デッキを削除せずに分類できます。

反映処理は一つのトランザクションで実行します。書き込み直前に変更前データとの一致を確認し、作成・改名・移動を行います。変更件数と全データを照合してから確定し、失敗した場合は全変更を取り消します。

### 4. ローカル検証と本番の事前照合を行う

コマンド例は fish shell の構文です。今回保存したスクリプトを使用する場合は、作業ディレクトリを指定します。

```fish
set chunk_work_dir "$HOME/.Codex-works/anki-chunk-levels"
bun test "$chunk_work_dir/migration.test.mjs"
bun --env-file=.env.local "$chunk_work_dir/migrate.mjs" dry-run
```

ローカル検証では、ファイル形式の SQLite データベースを使用します。移動後も本文・学習履歴・対象外カードが一致すること、再実行で重複しないこと、元構成へ復元できることを確認します。取得後の学習履歴の変更を検知して停止することと、途中の失敗でデッキの作成・改名も取り消すことを確認します。

`dry-run` は本番を書き換えません。`ready` は変更前データとの一致、`already applied` は分類後の期待値との一致を表します。不一致の場合は、最新データを再取得して差分を確認します。

### 5. 本番へ反映して再検証する

事前照合が `ready` になった場合に、反映を実行します。

```fish
bun --env-file=.env.local "$chunk_work_dir/migrate.mjs" apply
```

反映後は別の実行で本番に接続し、分類後の期待値と照合します。

```fish
bun --env-file=.env.local "$chunk_work_dir/migrate.mjs" verify
```

`verified` を確認したうえで、反映後データを `after.json` に、検証結果を `verification.json` に保存します。今回のスクリプトは標準出力へ結果を返すため、これらの保存は別途行います。

カード総数、レベル別件数、移動先の所属、本文と全学習履歴、対象外デッキとカードの不変性を確認します。アプリを再読み込みし、3フォルダーから教材を選択できることも確認します。

### 6. 必要な場合に元の構成へ戻す

復元するときだけ、次のコマンドを実行します。

```fish
bun --env-file=.env.local "$chunk_work_dir/migrate.mjs" rollback
```

復元処理は元デッキ名とカードの所属を戻し、今回作成したデッキが空であることを確認して削除します。

今回の `dry-run`・`apply`・`verify`・`rollback` は、保存時点の対象所有者の全データと厳密に照合します。反映後に学習や編集が行われた場合も不一致になるため、その失敗だけでは分類の異常と判断できません。最新の学習履歴を保持したうえで差分を確認し、古いバックアップで上書きしないでください。

## 今回の反映結果

2026年9月14日の反映直後の検証結果は次のとおりです。

| フォルダー | カード数 | デッキ数 |
| --- | ---: | ---: |
| チャンク B1 | 155 | 13 |
| チャンク B2 | 160 | 14 |
| チャンク C1 | 36 | 13 |
| 合計 | 351 | 40 |

元の14デッキを40デッキに分けました。対象所有者の全795枚を照合し、カード本文と学習履歴を保持しました。対象外の444枚と15デッキも変更前と一致しました。

ローカルの3テスト・14検証が通過しました。本番反映後の再接続による全件照合も通過しました。アプリの `groupDecks` を使った3フォルダーへの分類は確認しましたが、この作業ではブラウザ操作による画面確認は実施していません。

## 今後の教材追加で引き継ぐこと

新しく生成するチャンクも、本書の分類基準と命名規則を使い、教材ごと・レベルごとに分けます。新規カードの取り込みには既存のインポート用スクリプトを使えますが、今回の移動スクリプトは新しい教材の自動分類には対応していません。

[既存のカード生成手順](../.claude/skills/generate-ja-en-cards.md)には、レベル分類前の `チャンク::...` という名前が残っています。チャンクの分類と命名については本書を参照してください。
